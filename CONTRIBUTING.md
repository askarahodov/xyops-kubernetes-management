# Вклад в проект

## Рабочий процесс

1. Создайте ветку от актуальной `main` с именем `agent/<краткое-название>` или `feature/<краткое-название>`.
2. Не изменяйте существующие Plugin ID, Event ID и Workflow node ID без отдельной миграции и описания обратной совместимости.
3. Для нового Event Plugin добавьте понятные `title`, `description`, `notes`, подписи полей и ограничения операции.
4. Для нового Workflow добавьте отдельный Markdown-документ с назначением, входными параметрами, выходными данными, RBAC и ограничениями.
5. Не добавляйте в Git токены, kubeconfig, приватные ключи, сертификаты с приватным ключом и содержимое Secret Vault.

## Обязательные проверки

Перед Pull Request выполните:

```bash
npm test
npm run check
npm pack --dry-run
```

Все JSON/XYPDF должны разбираться без ошибок, а Workflow должны ссылаться на существующие Plugin ID.

## Безопасность Kubernetes

- Используйте отдельный ServiceAccount и минимальный RBAC.
- Не добавляйте произвольный `kubectl`, `exec`, чтение Kubernetes Secrets или применение произвольных manifests без отдельного обоснования и защитных ограничений.
- Изменяющие кластер операции должны требовать явного подтверждения.
- Массовые и удаляющие операции должны поддерживать dry run, повторную проверку объектов и лимит количества изменений.
- Токены и пароли не должны попадать в Job output, таблицы, `description`, `details` или логи.

## Импортируемые файлы

Plugin-файлы импортируются раньше Workflow, которые ссылаются на их Plugin ID. При изменении порядка импорта обновите README и соответствующую инструкцию.

## Pull Request

В описании PR укажите:

- что изменилось;
- зачем это нужно;
- какие операции изменяют кластер;
- какие новые RBAC-права требуются;
- какие команды проверки выполнены;
- какие XYPDF необходимо переимпортировать в xyOps.

# Политика безопасности

## Какие данные считаются секретами

Не публикуйте в Issues, Pull Requests, Job logs и Git:

- `KUBE_TOKEN`;
- kubeconfig;
- ServiceAccount token;
- приватные ключи;
- пароли;
- сертификаты, содержащие приватный ключ;
- содержимое Secret Vault;
- внутренние адреса и данные кластера, если их раскрытие запрещено политикой организации.

## Сообщение об уязвимости

Для уязвимостей, связанных с обходом подтверждения, раскрытием токена, избыточным RBAC, удалением неподходящих ресурсов или выполнением непредусмотренных команд, используйте приватный канал **Security → Report a vulnerability** в GitHub.

Не создавайте публичный Issue с рабочим токеном, kubeconfig или подробностями, позволяющими получить доступ к кластеру.

## Если секрет уже раскрыт

1. Немедленно отзовите или замените токен.
2. При необходимости удалите и пересоздайте ServiceAccount.
3. Проверьте Kubernetes Audit Logs и историю запусков xyOps.
4. Удалите секрет из Secret Vault и создайте новое значение.
5. Удаление секрета только из последнего Git commit недостаточно — считайте его скомпрометированным.

## Поддерживаемая версия

Исправления безопасности вносятся в текущую версию ветки `main`. Для production рекомендуется использовать commit или release, который был проверен в вашем тестовом кластере.
